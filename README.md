**第三版（V3 —— 当前在线版本）**：视觉沿用第二版的黄白杂志风，在首页新增第 05 节「意见反馈」。

- 访客要填 **5 项**：① 名字或昵称（可留空，默认匿名访客）② 与主页主人的关系 ③ 本条反馈针对的设备 ④ 反馈内容 ⑤ 提交时间（自动生成）。
- 隐私承诺（写在同一区的隐私卡里）：反馈**不公开**、他人看不到也删不掉；填了联系方式才会回复；可以完全匿名。
- **前端只写不读**：`GET /api/feedback` 一律返回 405，公开接口永不返回联系方式；只有作者本地后台能看到全部字段。
- 数据通道**按域名自动识别**（`js/feedback-config.js` 里的 `window.pickFeedbackMode()`）：**公网域名与 `file:` 打开用 `supabase`** —— 走 Supabase 的 `anon public` 公开密钥，RLS **只允许 INSERT、禁止 SELECT**，匿名读不出来；**本机地址（`localhost` / `127.0.0.1` / `::1` / `192.168.*` / `10.*` / `172.16–31.*`）自动用 `local`** = 本地 `server.py`（离线演示 / 自测），不需要手改配置。
- **线上反馈在哪里看**：Supabase 控制台 → Table Editor → `public.feedback`（也可用 SQL Editor 查询或导出 CSV）。线上站点是纯静态托管，所以**没有**部署在线的作者后台页面。
- 本地备用后台 `http://127.0.0.1:8000/admin?token=<令牌>`：统计卡 + 5 列表格 + 标记已读 / 已解决 + 删除单条 + 导出 CSV；它读的是本地 SQLite，**看不到线上反馈**。令牌存在 `db/admin_token.txt`，**不提交仓库**。

## 本地运行（含反馈后台）

```powershell
python server.py --port 8000        # 启动本地服务（网页 + 反馈接口）
# 访客页：  http://127.0.0.1:8000/
# 管理后台：http://127.0.0.1:8000/admin?token=<db/admin_token.txt 里的令牌>
# 导出 CSV：http://127.0.0.1:8000/export?token=<令牌>
```

- 直接双击 `index.html` 也能看页面，但**反馈提交需要上面的服务**（本机 http 访问会**自动**走 `local` 通道，无需改配置）。
- 想走线上 Supabase：把 `db/supabase_feedback.sql` 在 Supabase 的 **SQL Editor** 执行建表，并确保 `js/feedback-config.js` 里的 `supabaseUrl` 与 `anon public` key 正确——**公网域名与 `file:` 打开会自动用 `supabase`**（本机地址仍自动用 `local`）。⚠️ 现有 Supabase 项目已暂停/不存在，需先重建项目。
- ⚠️ **截图 / 预览前先确认服务在跑**：服务没起时浏览器只会给「无法访问此页面 · 127.0.0.1 拒绝连接」，看起来很像页面渲染坏了。

## 怎么用

- 前期：把收集的资料放进**材料分类目录**对应的文件夹。
- 想把 Word / PDF / 网页 / 图片转成 Markdown？放到 `04-文档原件/`，之后可统一转成 Markdown 存到 `05-Markdown内容/`。
- 未来开发时，再使用 `网页骨架` 部分的代码。

## 文件自动转 Markdown

DeepWorks 自带转换工具（`dw-markitdown`），支持 Word、PDF、PPT、Excel、网页、图片等转成 Markdown。你后续把材料放入对应文件夹后，我可以帮你批量转成 Markdown，存到 `05-Markdown内容/`。
